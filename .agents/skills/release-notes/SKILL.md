# Release notes

Use the requested release/version scope and verified source material. Group changes only where useful to the audience. Highlight actual breaking changes and meaningful user impact; do not imply unverified benefits or deployments.

Return the requested draft and concise source gaps. Ordinary implementation handoffs do not require this skill, and drafting notes does not authorize publishing them.

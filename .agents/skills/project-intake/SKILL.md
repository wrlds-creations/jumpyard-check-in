# Project intake

Produce enough confirmed context for the requested phase. Inspect existing facts and code first; ask only for missing decisions or facts that block the work. Unknown unrelated fields can remain TBD.

Use the relevant categories in [the question bank](../../../references/project-intake-questions.md) or [extended intake template](../../../references/project-intake-template.md). Neither is a mandatory questionnaire.

Update the owning PROJECT_CONTEXT.md section with confirmed answers. Keep hard constraints visible in Must know. Record meaningful choices in DECISIONS.md; distinguish a new explicit user decision from an assumption. Do not invent customer, billing, cloud or data details. End with the remaining blocker or next concrete implementation step.

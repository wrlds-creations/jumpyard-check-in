# Followup Policy

Operational work is not tracked in this file. New out-of-scope findings that may become work must be captured as unapproved GitHub Project draft issues in the private [JumpYard Check-in Project](https://github.com/orgs/wrlds-creations/projects/5). A draft is planning material only; implementation starts only after Love approves the scope and it is converted to a repository Issue.

Approved work is tracked by its GitHub Issue and Project fields. Completed legacy followups remain in [docs/history/followups-done.md](docs/history/followups-done.md), and the one-time reconciliation is preserved in [docs/history/github-project-migration-2026-07-14.md](docs/history/github-project-migration-2026-07-14.md).

## Durable External Gates

Provider decisions, credentials, approvals, and other facts that must remain durable outside the operational queue are maintained under [External Gates](docs/roadmap/backlog.md#external-gates). They are dependencies, not tickets and not implementation approval.

Do not recreate a mutable followup table here. Use the Project for status, priority, work type, track, owner, and candidate scope; use repository documentation only for durable facts, external gates, and historical evidence.
